# Create mart in PySpark — витрина идентификаторов пользователей

## Описание
Пет-проект на **PySpark / Spark DataFrame API**, который строит витрину, максимально содержащую идентификаторы пользователей веб-сайта (ИНН, хэши ИНН, телефон/email (md5), user_uid (GAID/IDFA), набор cookie и служебные id из источников).

Основа витрины — **Витрина A** (web-события), партиционированная по датам. Дополнительно используются витрины B–G как внешние источники идентификаторов.

Ключевое требование: алгоритм должен запускаться **ежедневно**, добавлять новые данные и **удалять дубликаты**, так как нам важно зафиксировать пользователя один раз и при этом учитывать новые устройства/куки при повторных визитах.

---

## Архитектура данных (логические слои)
- **RAW**: сырые события витрины A в формате JSON, партиционирование по датам (`YYYY_MM_DD`).
- **STAGE**: приведение типов/нормализация (опционально: нормализация гео/страны, очистка строк, dedup).
- **MART**:
  - витрины B–G (синтетика источников)
  - итоговая витрина `main_marts` — “витрина идентификаторов пользователя”.

---

## Источники (по ТЗ)

### Витрина A (основа)
Партиционирование по датам. Ключевые поля:
- `raw_cookie`: массив объектов вида `[{key, value}, ...]` (cookies + org_uid/user_uid/phone/mail)
- `event_type`: `SUBMIT`, `REGISTER`, `SUBMIT_MD5`
- `data_value`: хэш ИНН (sha256 для `SUBMIT`, md5 для `SUBMIT_MD5`), иногда `NULL`
- `event_action`: `pageview`, `event`, `login-check-otp`
- гео/устройство: `geocountry`, `city`, `user_os`, `systemlanguage`, `geoaltitude`, `meta_platform`, `screensize`
- `timestampcolumn`: дата события

### Витрины B–G (справочники/внешние источники)
- **B**: `{id, inn}`
- **C**: `{id, cookie_a}`
- **D**: `{id, inn}`
- **E**: `{id, hash_phone_md5}`
- **F**: `{id, hash_email_md5}`
- **G**: `{id, user_uid, match_code}` где `match_code ∈ {GAID, IDFA}`

---

## Что реализовано

### 1) Генерация синтетических данных (RAW + источники)
Синтетика — часть задания: данные генерируются так, чтобы имитировать реальные веб-события и наличие/отсутствие идентификаторов.

- Генерируется витрина A (JSON) на несколько дней с партиционированием по датам.
- `raw_cookie` заполняется сложной структурой (cookies + org_uid + user_uid + phone + mail).
- Генерируются значения `event_type` и `data_value` (md5/sha256 ИНН в зависимости от типа события).
- Генерируется гео и параметры устройства.
- По необходимости создаются источники B–G.

### 2) Построение витрин и итоговой витрины идентификаторов
В ноутбуке построения:
- Чтение витрины A из партиций за нужный период.
- Подготовка/трансформации через Spark DataFrame API.
- Построение витрин B–G.
- Сборка итоговой витрины `main_marts` через join’ы и извлечение значений из `raw_cookie`.

**Итоговая витрина `main_marts` содержит максимум идентификаторов:**
- `inn` (и/или `inn_hash`),
- `hash_phone_md5`, `hash_email_md5`,
- `user_uid` (GAID/IDFA),
- телефон/email (как исходные значения из cookie),
- `org_uid`,
- набор cookies (SA/FA/YM/FBP),
- `id` источников B–G (для трассировки).

### 3) Ежедневный запуск и дедупликация
Проект ориентирован на ежедневный запуск:
- новые партиции витрины A добавляются каждый день;
- итоговая витрина поддерживается так, чтобы **не хранить повторные визиты одного пользователя**, но учитывать новые идентификаторы/устройства (cookie/user_uid).

Дедупликация реализуется через оконные функции (Window) и выбор “актуальной” записи по ключу (например, по `inn`/`inn_hash`/`user_uid`) с учётом даты события.

---

## Структура проекта
В проекте 2 ноутбука:

1) `Generation_files_FIXED.ipynb`  
   Генерирует синтетические данные витрины A (JSON по датам) и/или витрин B–G.

2) `Create_data_marts_FIXED.ipynb`  
   Читает RAW данные, строит витрины B–G и формирует итоговую витрину `main_marts` (витрина идентификаторов).

---

## Как запустить (Google Colab)

### 0) Предусловия
Нужен Google аккаунт и доступ к Google Drive.

### 1) Запуск генерации RAW
1. Открыть `Generation_files_FIXED.ipynb` в Colab  
2. Запустить всё последовательно  
3. В результате на Google Drive появятся партиции:
   - `.../MyDrive/data/json/2026_02_10/`
   - `.../MyDrive/data/json/2026_02_11/`
   - …

### 2) Построение витрин
1. Открыть `Create_data_marts_FIXED.ipynb`  
2. Подмонтировать Drive (`drive.mount('/content/gdrive')`)  
3. Убедиться, что `PATH_TO_FILES` указывает на папку с RAW (`.../data/json/`)  
4. Запустить ноутбук до конца  
5. Получить итоговую витрину `main_marts` (и при необходимости сохранить её в Parquet/JSON)

## Результат
Итогом является витрина идентификаторов пользователей `main_marts`, которая агрегирует и связывает доступные идентификаторы пользователя (ИНН, хэши, phone/email, GAID/IDFA, cookies) из витрины A и справочников B–G, с поддержкой ежедневного инкрементального запуска и дедупликации.
